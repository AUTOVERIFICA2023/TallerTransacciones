Propósito del taller

Hoy vamos a realizar un taller guiado para entender cómo una transacción protege los datos cuando una operación tiene varios pasos. El ejercicio se trabaja en PostgreSQL y MySQL, y al final cada grupo debe pensar cómo aplicar este mismo concepto en su proyecto.

Objetivo 1

Objetivo 2

Objetivo 3

¿Qué es una transacción?

Una transacción es un conjunto de instrucciones SQL que deben ejecutarse completamente o no ejecutarse. Es como decirle a la base de datos: “haga todos estos pasos, pero si algo falla, devuelva todo como estaba”.

Ejemplo sencillo: en una transferencia bancaria no basta con descontar dinero de una cuenta. También debe sumarse a la otra. Si el segundo paso falla, el descuento debe deshacerse.

BEGIN / START TRANSACTION

Inicia la transacción. Desde este punto, los cambios todavía se pueden confirmar o deshacer.

COMMIT

Confirma definitivamente los cambios realizados.

ROLLBACK

Deshace los cambios si algo salió mal.

SAVEPOINT

Crea un punto intermedio para devolverse parcialmente.

ACID explicado sencillo

Atomicidad: todo o nada.
Consistencia: los datos quedan válidos.
Aislamiento: una operación no daña otra.
Durabilidad: lo confirmado permanece.
